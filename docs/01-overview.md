# Overview

## The product

Harkbell is a multi-tenant AI receptionist for small service businesses — a
dental practice, a vet, a garage, a funeral home. The pitch is narrow and
concrete: **a missed call is a lost booking**, so answer every call.

A business signs up, creates a workspace, walks an onboarding wizard that
collects who they are and what they sell, picks a voice, uploads what the agent
should know, and publishes. From that moment:

- A widget on their website lets a visitor talk to the agent in the browser.
- If they connect a phone number, callers reach the same agent on the PSTN.
- The agent answers questions from their knowledge, books into their real
  diary, takes messages, and hands over to a person when it should.
- Everything the agent did shows up in the dashboard as bookings, callbacks,
  contacts, conversations with transcripts, and knowledge gaps.

## What runs the calls

Harkbell does not implement speech. A self-hosted **Dograh** instance (git
submodule `dograh/`, v1.41.0) runs the media, the model orchestration and the
call graph. Harkbell's job is everything around it:

- generating and owning a purpose-built workflow per business on that engine,
- pushing speech-provider configuration into it from our environment,
- provisioning and routing phone numbers,
- serving the widget and minting the embed tokens it uses,
- answering the tool calls the agent makes mid-call,
- pulling completed runs back out and turning them into product data.

The browser never talks to Dograh with credentials. See
[Architecture](03-architecture.md#trust-boundaries).

## Domain language

These words mean specific things in this codebase. Use them precisely.

| Term | Meaning |
|---|---|
| **Business** | The tenant. Table `businesses`, addressed everywhere by `slug`. A user may belong to several. |
| **Workspace** | The UI for one business — `/app/:businessSlug/*`. Same thing as a business, seen from the dashboard. |
| **Membership** | A user's role in a business. Roles: Owner, Admin, Manager, Staff, Viewer. |
| **Agent** | The configured persona for a business: name, tone, voice, greeting, prompt, closing, escalation guidance. Table `business_agent_settings`. |
| **Workflow** | The graph on the Dograh engine that a call actually runs. Generated by us from the business's configuration; never hand-edited. |
| **Run** | One call on the engine. Identified by `runId`. Mirrored locally as a `call_records` row. |
| **Publish** | Turning the current draft configuration into the live agent. Writes a `business_config_versions` row and enqueues a sync. |
| **Sync** | Reconciling a business's desired workflow with what the engine holds. Decided by a config hash; performed by the worker. |
| **Outbox** | The `outbox_events` table. Every engine-touching side effect goes through it so it survives a crash and retries. |
| **Vertical** | A trade (dental, veterinary, …). Drives intake questions, defaults, and the safety rules in the agent's prompt. |
| **Knowledge** | Documents and text a business gives the agent to answer from. Uploaded here, processed by the engine, attached to workflow nodes. |
| **Knowledge gap** | A question a caller asked that the agent could not answer. Surfaced so the business can fill it. |
| **Callback** | A promise to ring someone back. Created by the agent mid-call or by staff. Dialable ones can be rung from the dashboard. |
| **Embed token** | A short-lived, server-minted credential the widget uses to start a call. The only engine-adjacent secret the browser ever sees. |

## Verticals

Eleven trades in `app/api/src/verticals.ts`, each carrying:

- `intakeFields` — what the demo and onboarding ask,
- `defaultServices`, `defaultGreeting`, `tone` — sensible starting configuration,
- `suggestedCallerScripts` — what to say when testing,
- `missedCallValue`, `emailCaseStudy` — marketing figures,
- and, most importantly, `VERTICAL_AGENT_RULES` — hard limits baked into the
  agent's global prompt. What a dental agent must never advise on. What counts
  as an emergency for a vet. How a funeral home's agent should speak.

Some verticals are `coming_soon` and are shown disabled in the demo.

## Business model

Three plans in `app/api/src/billing/plans.ts` — Free, Starter ($49), Pro ($149)
— differing on included minutes, phone numbers and seats. Stripe price ids come
from the environment, so a plan with no price id is simply not offered on that
deployment. Limits are enforced at the moment of acquisition (buying a number,
inviting a member), never retroactively.
